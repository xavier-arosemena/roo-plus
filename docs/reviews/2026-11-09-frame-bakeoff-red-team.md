## 1. Verdict

**(a) "Both frames are stable" — NOT SUPPORTED as written.** What the data support is much narrower: _one model family, given the identical brief string three times, returned the same slug three times in all six cells._ Three runs of one fixed input measure prompt determinism, not catalogue stability; stability across paraphrases, contexts or models was never tested, and the artefact-frame fixture that produced the B results no longer exists in the repository (R2). The word "conclusive" in [`§7`](2026-11-09-frame-bakeoff-run.md:352) directly contradicts the run's own [`§5.1`](2026-11-09-frame-bakeoff-run.md:318) ("eighteen trials … is not a sample"). Downgrade to: **"the procedure is executable and deterministic on these three inputs."**

**(b) "Neither frame is better" — NOT SUPPORTED, and the run should say "not tested" instead.** The three briefs have near-paraphrase owners in both catalogues, so the run could not produce a different decision, only a different word (R7). The one instrument that does point somewhere — the T-H rubric, reported 6/6 vs 3/6 — reverses to a tie when its own stated rules are applied consistently to its own quoted rationales (R4). "Inconclusive" is the correct word and the run uses it; "neither better" is a different, stronger claim that this data cannot carry.

**(c) The recommendation for the next test — DIRECTION SUPPORTED, ONE LOAD-BEARING CRITERION BROKEN.** "Stop writing more briefs of the same kind; discriminate, use a panel, add humans, add an outcome arm" is right and follows from the data. But acceptance criterion 1 — _"no slug in either selection block sharing a stem with the brief's head noun"_ ([`§7`](2026-11-09-frame-bakeoff-run.md:367)) — is broken in both directions, mechanically, on the run's own briefs: **B2 has zero stem overlap with any slug in either frame yet has a ready-made owner in both**, and **B1 overlaps `test-*` in both frames while its actual owners (`debug`, `bug-report`) share no stem**. A filter that admits B2 and rejects B1 is not a discriminator; the next run as specified would reproduce this null.

**Overall label: HARDEN.** Withdraw claim (b), re-label claim (a), and replace the ownership test in the next-test spec (R1, Appendix A). The run itself does not need to be re-run to be useful: as a pilot and as a defect-finder it is sound, and §5 shows its author knew most of what was wrong with it.

## 3. The single most damaging objection

### Ownership is tested by word overlap at every stage, so the procedure can only confirm that its author recognises his own names.

The run's central construct is "does this brief have a ready-made owner?" It is answered four times, and each time by lexical proximity:

1. **The briefs.** B1–B3 are paraphrases of specific `whenToUse` lines. `bug-report`'s line is "Use when **something fails** and **the cause is unknown**; produce evidence, not a guess" ([`artefact.selection-block.txt`](../../test-fixtures/frames/artefact.selection-block.txt:12)); B1 is "CI is red on a test that passes locally. I have no idea why." `benchmark`'s line is "Use when a **performance**, cost or build-time **budget is missed**" ([`line 11`](../../test-fixtures/frames/artefact.selection-block.txt:11)); B2 is "Make this endpoint 3× faster." The brief-to-entry distance is a synonym step, not a routing inference.

2. **The key.** "Intended owner" was fixed in advance — good practice — but it is a judgement, and the artefact frame's own vocabulary contests one cell. `flake-record` reads "Use when a test fails **intermittently** and **blocks others from merging**" ([`line 17`](../../test-fixtures/frames/artefact.selection-block.txt:17)) — the canonical description of a test that passes locally and fails in CI. The trial rationale for B-B1-2 explicitly weighs it ("before guessing environment or **flake**"). Both readings are defensible; the run records one as correct 3/3. Under the other, frame B has an internal D3 collision on B1 and the headline becomes 15/18, not 18/18.

3. **The rubric.** Criterion 1 is operationalised as "does the winning mode _name_ repeat a word the user used". A is credited for `performance` against "faster"; B is not credited for `benchmark` against the same word, and no credit is given at all for the fact that `benchmark`'s line _contains_ the word "performance". Criterion 3 is operationalised as "does the rationale name a boundary". A's three qualifying clauses are counted; B's two functionally identical clauses ("rather than a guess", "before guessing environment or flake") are not. Scored consistently: **A 3 / B 3 on the two criteria the run calls measured**; A 5 / B 4 only if the explicitly unmeasured criterion 4 is included.

4. **The proposed fix.** Acceptance criterion 1 for the next run requires "no slug … sharing a stem with the brief's head noun, verified mechanically". Mechanical check on the run's own briefs:

| Brief | Brief stems                        | Stance stem hits                 | Artefact stem hits        | Verdict of the proposed filter                                                                                          |
| ----- | ---------------------------------- | -------------------------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| B1    | `test`, `passe`, `locally`, `have` | `test-author`, `test-strategist` | `test-suite`, `test-plan` | **rejected** — but its real owners (`debug`, `bug-report`) share no stem, so the filter rejects it for the wrong reason |
| B2    | `endpoint`, `fast`                 | none                             | none                      | **accepted as owner-free** — yet `performance` and `benchmark` are ready-made owners                                    |
| B3    | `explain`, `module`, `structur`    | `explain`                        | none                      | **rejected for stance only**, asymmetric                                                                                |

The filter is over-inclusive on B1 and under-inclusive on B2. It measures string overlap, which is precisely the property the briefs were written to have.

**Failure scenario it implies.**

1. The next run is built to the stated acceptance criteria. Eight briefs are selected; six pass the stem filter, because semantic owners rarely share stems — that is what makes a mode name a _label_ rather than a copy of the request.
2. The panel runs. Each of the six has a paraphrased owner in both frames. Both frames pick correctly. The result is another clean null, now with 3 model families and 8 humans, and therefore far more expensive and far more credible.
3. The tie is written up as "the frames are equivalent on routing". Because a tie cannot justify the cost of restructuring, the incumbent frame is retained by default.
4. The frame question is closed without ever having been asked. The one brief in the set that would have decided it — one where the stance frame has an owner and the artefact frame genuinely has none — is the brief that the filter could not distinguish from the others.
5. Six months later, the artefact catalogue is still a document nobody uses, and the record says it was tested twice and lost nothing, which is true and useless.

**What would demote this from FATAL to SERIOUS.** Replace "does the brief share a stem with a slug" with "for each of the 92 entries, does this entry's `whenToUse` admit this request", answered by readers who did not write either catalogue, and report the _number_ of admitting owners per frame. That single change makes both the key and the brief-selection defensible, and it is two hours of work. Appendix A turns this into a runnable procedure.

## 4. What the run does establish, stated as narrowly as the evidence requires

1. **The generator is deterministic and idempotent on the axis-stance catalogue.** `axis-stance.roomodes` hashes to `30315cd2…06edc6` and the selection block to `e6836d8b…8c27590`, exactly as the report records; 45 entries, 45/45 `whenToUse` verbatim, schema-valid. Its count guards and YAML round-trip check ([`generate-frame-fixtures.mjs`](../../scripts/generate-frame-fixtures.mjs:300)) are real: a silent partial parse cannot pass them.
2. **The artefact fixture, _as it existed at trial time_, was a 47-entry, schema-valid catalogue of which 35 lines were verbatim and 12 were template-derived at a mean of 60.5 characters.** The decomposition is exact: 2,736 over 35 lines (78.2 mean) plus 726 over 12 (60.5 mean). That fixture no longer exists on disk (R2).
3. **Given one identical brief string and one flat list, one model family returns one slug in the requested JSON, 18/18, with no refusal and no ranked list.** This establishes that the format is executable and the prompt is obeyed. It does not establish that the catalogue is clear, because the prompt forbids the answers that would show ambiguity.
4. **The chosen slug matched the pre-stated key 18/18.** Read narrowly: both catalogues are consistent with their author's intent on three requests whose owners are near-paraphrases of their entries. It does not establish correctness, because the key is one of several defensible readings (R1).
5. **The frames agree 3/3 that a matching owner exists, and 0/3 on its name — the latter by construction.** The slug sets are disjoint, so 0/3 was fixed before the first trial. The 3/3 on existence is the informative half and the run reports it.
6. **Cost direction.** Under every measurement I could construct, frame A is more expensive: proxy 5,103 vs 4,648 (+9.8%), production rendering 6,269 vs 5,743 (+9.2%), Σ`whenToUse` 4,208 vs 3,836 (+9.7%). The report's "+19.4%" is a stale-object plus omitted-name artefact. **The direction survives every correction; the magnitude does not.**
7. **A real defect was found and fixed.** Twelve artefact `whenToUse` lines had never been drafted, and the frame therefore looked cheaper than it was. This is the run's single best contribution and it is exactly the kind of thing a self-review is supposed to catch.

## 5. Where the run survives

Claims I attacked and could not break:

- **The count guards.** I tried to construct a silent partial parse through the section classifier and the cell-count check; every route I found either throws or trips the expected-count exit. [`classifySection`](../../scripts/generate-frame-fixtures.mjs:125) disabling unknown headings is a correct defence, not a wart.
- **The 45/47 counts and the 4,208 / 2,736 arithmetic.** Recomputed from both markdown files and from the fixtures; exact to the character. The stance catalogue's own 4,208 is independently confirmed by the fixture.
- **"The artefact frame looked cheap partly because twelve lines were unwritten."** True, and I could not break the direction of the correction: the derived lines were _shorter_ (60.5 vs 78.2), so the defect favoured frame B, as the report says.
- **The derived-lines tally (45/45, 35/47, 12 derived).** Correct, and it is stated in the report's own prose rather than buried.
- **"No human ever saw either catalogue."** True, and load-bearing: D4 criteria 2, 5 and 6 are unmeasured, and the run says so three times.
- **"Every brief had an equivalently named owner in both catalogues, so it never had to discriminate."** True and plainly stated ([`§5.6`](2026-11-09-frame-bakeoff-run.md:323)). I looked for a reading under which the run claimed otherwise and did not find one.
- **The refusal to declare a winner, and the instruction to stop writing more briefs of the same kind.** Correct, and the most valuable sentence in the report.
- **The built-in-slug confound on `debug`/B1.** Correctly identified and correctly excluded from clean evidence. My only addition is that it is wider than one brief (R9).

A clean pass on everything above is the reason this review can be specific about the four things that did not survive.

## Appendix A — the minimum valid test

The smallest procedure that could actually discriminate the frames, in the order that fails fastest and cheapest.

**A0. Ownership audit (2 engineer-hours).** Three readers who wrote neither catalogue classify all 92 entries against 10 requests: _does this entry's `whenToUse` admit this request?_ Output per (request, frame): the number of admitting entries and their slugs. A request is **owner-free** only when it admits ≤1 entry per frame. This replaces stem matching and is the only step that must not be skipped.

**A1. Internal collision count (free, computed from A0).** For each frame, the mean number of admitting entries per request. This is the D3 coin-flip quantity the brainstorm already names ([`§5.1`](../modes-catalogue-brainstorm.md:123)), measured on the requests that expose it rather than on the author's chosen pairs — the current pair list (A11/A12, A20/A21, …) does not include `bug-report`/`flake-record`, which B1 exposes.

**A2. The discriminating selection arm (≈1 day orchestration).** 10 requests, of which 5 are owner-free in both frames, sourced from outside the repository (issue titles, forum posts, support mail) so they cannot be paraphrases of the catalogue. Three surface paraphrases each. Two frames × 3 model families × 3 runs. The prompt must permit **`NO_OWNER`**; the rate of that answer per frame is the completeness measure. Report per family, never pooled. Cost: 10 × 3 × 2 × 3 × 3 = 540 short selections.

**A3. The outcome arm (1–2 days review, and it is the expensive part).** Only for requests where the frames chose different _jobs_, not different labels. Requires authored `roleDefinition` / `customInstructions` for the winning entries — **with the current template doctrine the arm is vacuous** (R6), because both winners share one charter skeleton and one grant.

**Falsifiers, stated before running.**

1. If the top-1 owner differs between frames on fewer than 1 of the 5 owner-free requests, the frame choice is **not decided by routing**; escalate to the human tree test (findability) or to the "frames are views, not rivals" hypothesis in [`§5.1`](../modes-catalogue-artefact-frame.md:196). Report a tie — do not report "equivalent".
2. If every winning pair has the same `groups` and the same doctrine skeleton, the frame changes the label only, and the bake-off is the wrong instrument.
3. Declare the tie margin and the _n_ before the run; with 5 owner-free requests, one request is 20 percentage points, so a 10-point margin is undetectable and must not be used as the tie rule (the run's own criterion 4 sets a 10-point margin — unachievable at that _n_).

**What result makes the frame question moot.** If, on the owner-free requests, both frames return `NO_OWNER` at similar rates, the two frames are equally incomplete; the difference between them is then a naming and discoverability question, decidable by 8 humans in an afternoon with a tree test, and no further bake-off is warranted. That is the cheapest possible resolution and it should be checked _before_ A2, by running A0 on owner-free requests and counting whether either frame can even represent them.

## Appendix B — method checklist for the next run

Tick before any trial; each item corresponds to a finding above.

1. **Pre-registration file committed first** — hypothesis, metric, _n_, tie rule, falsifier, and the key, with a `git log` timestamp earlier than the first trial (R8).
2. **The key is authored by someone who wrote neither catalogue**, and each brief records _every_ defensible owner, not one (R1).
3. **Ownership is measured semantically, not lexically** — the A0 audit table is committed alongside the briefs (R1).
4. **Every brief is checked for internal collisions in both frames before it is admitted**; a brief that admits two entries in one frame is a data point, not a valid discriminator (R7, R1).
5. **Three surface paraphrases per brief**, one of which uses none of the catalogue's words. Stability is agreement across paraphrases, not across repeats of one string (R3).
6. **The reading agent's system prompt is stripped of the mode list**, or every winning slug that is a built-in is reported separately and excluded from the headline. The stance fixture contains four built-ins: `architect`, `code`, `debug`, `orchestrator` (R9).
7. **The input is the production rendering** (`  * "Name" mode (slug) - whenToUse`), and cost is reported three ways: Σ`whenToUse`, rendered, and at the 250-char ceiling — never at the achieved mean alone (R5).
8. **Two scorers, at least one blind to which frame is "ours"**, scoring the criteria _as written_; publish both totals and the disagreement; report any criterion that was not measured as unmeasured, and keep it out of the total (R4).
9. **Fixtures are regenerated in the same commit as the trials, with hashes recorded**, so the tested object is always reconstructible; a trial whose input hash no longer reproduces is void (R2).
10. **One model family is a pilot, never a panel**; report per-family results separately and never pool, and state the per-trial reliability bound the design can actually detect (R3).
