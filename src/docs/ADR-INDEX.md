# Roo+ Architecture Decision Records (ADRs)

This directory collects Architecture Decision Records (ADRs), architecture
reviews, and planning references for the Roo+ fork. ADRs document **why** a
decision was made (Context → Decision → Consequences). For the separation
between `src/docs/` (decisions), [`docs/`](../../docs/) (living operational
docs), and [`plans/`](../../plans/) (temporal plans/execution records), see the
[Documentation & ADR Protocol](README.md). To write a new ADR, copy
[`ADR-TEMPLATE.md`](ADR-TEMPLATE.md).

## Contributing an ADR

1. Copy the template — [`ADR-TEMPLATE.md`](ADR-TEMPLATE.md) — into `src/docs/` as
   `adr-<kebab-case-slug>.md` (or `arch-review-<slug>.md` for a review).
2. Fill in **Context → Decision → Consequences** (add a Migration Strategy when
   the decision lands incrementally). Follow the status vocabulary in
   [`README.md`](README.md): Proposed → Accepted → Deprecated → Superseded.
3. Add a row to the index above (keep the table sorted newest-first).
4. Link the ADR from the relevant `CHANGELOG.md` release entry so readers can trace decisions back to their rationale.
